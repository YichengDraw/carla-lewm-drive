阶段计划

Phase 1: 车道边界闭环修复

目标：让模型在 route6 弯道处从约 200m 提升到至少 300m，再进入 1km 评估。退出条件是 failure-tail sign acc 明显提升，单次 closed-loop 不再在同一车道边界压线。

当前动作：先用 scripts/run_aux_tail_gate.py 续跑 ft35 retry 的 tail220/tail190 门控；如果不明显优于 ft33，就用两个 save-frames 配置采样 hard-boundary failure frames，转成 teacher HDF5 后训练 ft36 temporal_delta_hardboundary。如果 ft36 仍失败，再进入 BCE sign 或显式 boundary bins。

Phase 2: 1km no-traffic / green-light

目标：在五条控制器验证路线跑满 1km。退出条件是 mean_infraction_free_distance_m = 1000m 且 5/5 primary safety success。

当前状态：暂停在 learned model 未过 300m 的前置 gate。oracle lane_keep 证明场景可达。

Phase 3: 红绿灯

目标：取消 force_green_lights，让 red-light violation 成为硬失败。只有 Phase 2 通过后进入。

Phase 4: 多天气与更大 ViT

目标：验证视觉鲁棒性或容量瓶颈。多天气混训、ViT small/base 都保留，但先看单天气小范围是否能成功；当前 ViT-base 是容量/预训练特征方向的受控试验。

名词速查

Term解释
LeWMlatent world model，用图像 latent 和动作预测未来 latent。
ViT tiny当前小模型视觉编码器，参数和显存都较小，适合先验证任务定义。
ViT-base frozen使用 ImageNet-21k 预训练 ViT-base 作为冻结视觉 encoder，只训练驾驶后端；用来测试视觉特征容量是否是瓶颈。
sidecar独立监控进程，从本地 metrics.csv 读训练曲线并上传 W&B，避免训练主进程被 W&B SDK 干扰。
patchlane让 lane 预测头更直接使用 ViT patch token，增强局部车道线几何信息。
tail150 / tail180把失败前最后 150 或 180 帧转成 teacher 数据加入训练，专门修补闭环尾部状态。
hardboundary更靠近车道边界的失败帧，当前指大约 0.4-0.5m lane offset 的状态；这些状态比普通尾部数据更接近 lane invasion。
temporal_delta让模型预测的 lane/heading 逐帧变化匹配真实逐帧变化，减少闭环时同一弯道里正负号来回跳。
cls_mean把 ViT 的 CLS token 和 patch token 平均池化拼接，给 lane 几何更多空间信息。
aux从当前图像 latent 读出 speed/lane/heading 等状态的辅助头。
pred_aux从预测未来 latent 读出下一步状态，直接服务 rollout lane-keep。
controlsign新增 loss：由预测 lane/heading 算出的 steering 必须与 teacher steering 同方向。
appliednext把闭环 eval trace 中下一行实际 applied action 作为当前状态的动作标签，避免 teacher/action 与真实转移不匹配。
tailgate针对失败尾部分布的训练和筛选策略；当前配置大量重复失败帧，并按 validation checkpoint 做 failure-tail 排名。
thr002低 active threshold 备选配置，把 control-sign loss 的有效 steering 门槛从 0.08 降到 0.02，用来覆盖小但持续累积的偏移。
lane invasionCARLA 车道线侵入传感器；现在作为 primary safety failure 记录和可选停止条件。
DAgger把模型闭环失败时遇到的状态重新用 teacher 标注，再加入训练，修补分布偏移。
IFDinfraction-free distance，首次硬违规前行驶的距离。
route6当前最主要的单路线诊断场景；模型在约 200m 的弯道/车道边界处反复 lane invasion。
W&BWeights & Biases，用于在线记录 loss、验证指标、run 链接和配置。
